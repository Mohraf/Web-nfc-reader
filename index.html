Why a plain web page can't do this, and what does

    

      

        
Passport and ID card chips are smart cards. To get anything out of one, the reader has to run a challenge–response handshake keyed from the MRZ or CAN (BAC or PACE), then send every command encrypted and signed (secure messaging). That needs raw APDU access to the chip.

        
Web NFC in Chrome only reads and writes NDEF messages, so it sees a passport as an empty tag. The WebToNative NFC add-on (WTN.NFC.read) also returns tag text only. Neither can send APDUs.

        
This app runs the whole ICAO 9303 protocol in JavaScript. The native part is a small Android shell that forwards APDUs to the chip and nothing else. The same web code runs unchanged in the browser simulator.

Trusted issuer certificates (CSCA)

        
Passive authentication checks the chip's signature with the document signer certificate it carries. Add your country's CSCA certificate (.cer, .der or .pem) to also verify who issued it. A demo CSCA for the simulator is built in.
